# Zaapo!

Соревновательная игра «соедини точки»: онлайн-дуэли, в которых побеждает скилл.
Мир игры — «Цепь»: поле — плата, цепочка — ток. Маскот — молния Заппо.
(Ранее проект назывался Doton; репозиторий и внутренние пакеты пока хранят старое имя.)
Концепция: [CONCEPT.md](CONCEPT.md). История поиска визуала: `docs/design-*.html`.

Играть: https://gogomachine.github.io/dottony/

## Структура

| Пакет | Что это |
|---|---|
| `packages/core` | Правила игры: поле, цепочки, фазы, перегрузка с каскадом множителей, детерминированный RNG. Чистые функции без зависимостей, общие для клиента и сервера. |
| `packages/protocol` | Контракт клиент ↔ сервер: zod-схемы запросов и типы ответов. |
| `apps/client` | Клиент: Vite + TypeScript, Canvas-рендер, темы «Чертёж»/«Графит», Telegram Mini App. |
| `apps/server` | Сервер: Fastify + libSQL. Ежедневный вызов, дуэли по WebSocket, проверка каждого хода через ядро, таблицы дня, вход через Telegram / гостём. |

## Команды

```bash
pnpm install
pnpm dev                        # клиент на http://localhost:5173
pnpm --filter @doton/server dev # сервер на http://localhost:3000
pnpm test                       # тесты ядра и сервера (vitest)
pnpm typecheck                  # проверка типов во всех пакетах
pnpm build                      # сборка
```

Локальная игра с сервером: запусти сервер и собери клиент с
`VITE_API_URL=http://localhost:3000 pnpm dev`.

## Деплой

- **Клиент** публикуется на GitHub Pages автоматически при каждом пуше
  (`.github/workflows/deploy.yml`). Адрес API задаётся переменной
  репозитория `DOTON_API_URL` (Settings → Secrets and variables →
  Actions → Variables); без неё клиент работает в оффлайн-режиме.
- **Сервер** — `render.yaml` для Render (Blueprint, free-план). Секреты
  `JWT_SECRET`/`DAILY_SECRET` генерируются сами.
- **База.** По умолчанию libSQL пишет в файл `doton.db` рядом с приложением;
  на бесплатных хостингах без постоянного диска он исчезает при
  перезапуске. Чтобы результаты жили, заведите бесплатную базу
  [Turso](https://turso.tech) и задайте `DATABASE_URL` (`libsql://…`) и
  `DATABASE_AUTH_TOKEN` — код и SQL те же.
- `TELEGRAM_BOT_TOKEN` добавляется вручную после создания бота.

## Статус

Этап 2 из [плана](CONCEPT.md#9-этапы): онлайн-дуэли.

- **Соло:** Спринт, Свободный режим, Ежедневный вызов (общий сид на сутки,
  одна попытка, таблица дня).
- **Дуэли:** матч 90 секунд на одинаковом поле, счёт соперника в реальном
  времени, подбор соперника и вызов друга по коду или ссылке `?room=КОД`.
  Каждый ход проверяется сервером через то же ядро, что и у клиента: счёт
  клиента не принимается на веру, уход из матча засчитывается поражением.
- **Призраки:** если живой соперник не нашёлся за 12 секунд, игрок получает
  матч против записи чужой дуэли — на её же сиде, поэтому поле ровно то,
  которое проходил соперник. Запись всегда честно помечена («· запись»).
  Пока записей нет, соперника отыгрывает Заппо примерно в силу игрока.
- Впереди: рейтинг и лиги, личный кабинет.
